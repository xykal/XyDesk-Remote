Kebijakan Privasi & Keamanan Data

Dokumen ini menjelaskan bagaimana XyDesk Remote menangani konfigurasi koneksi, kredensial, izin perangkat, dan keamanan komunikasi. Diterbitkan oleh XyVerse Technology Global.

Catatan cakupan

Dokumen ini menerangkan perilaku yang dimaksudkan oleh aplikasi, bukan hasil audit keamanan independen. Mode Koneksi PC/Host Agent masih eksperimental dan tidak tercakup oleh pernyataan jaringan RDP standar di bawah. Tinjau kode, izin, firewall, dan endpoint yang digunakan sebelum mengandalkannya.

1. Mode RDP standar dan jalur jaringan

Pada mode RDP standar, klien membuka koneksi ke host dan port atau RD Gateway yang Anda masukkan. Jika Anda mengonfigurasi gateway atau tunnel, lalu lintas akan mengikuti jalur tersebut. Jangan menganggap ini sebagai jaminan bahwa seluruh mode aplikasi memakai jalur langsung: perilaku Koneksi PC/Host Agent eksperimental perlu dievaluasi terpisah. Situs ini dan GitHub digunakan untuk distribusi rilis; itu berbeda dari jalur sesi RDP.

2. Penyimpanan Kredensial & Enkripsi Android Keystore

Apabila Anda memilih opsi untuk menyimpan kata sandi koneksi pada perangkat:

  • Kata sandi dienkripsi secara lokal menggunakan algoritma AES-256-GCM (`CredentialVault`).
  • Kunci enkripsi utama dibuat dan disimpan di dalam perangkat keras Android Keystore yang bersifat non-exportable (tidak dapat diekstrak keluar dari perangkat).
  • Kata sandi dan isi clipboard tidak pernah ditulis ke berkas log diagnostik aplikasi maupun URI log internal.
  • Pencadangan otomatis sistem Android dimatikan (`android:allowBackup="false"`) untuk mencegah salinan data sensitif berpindah ke penyimpanan cloud pihak ketiga.

3. Verifikasi Sertifikat Server (Trust-On-First-Use)

Saat terhubung ke server RDP, sidik jari (fingerprint) sertifikat TLS/NLA diverifikasi terhadap daftar kepercayaan lokal (`CertificateTrustStore`). Apabila sertifikat berubah atau belum dikenal, aplikasi menampilkan dialog konfirmasi eksplisit sebelum melanjutkan koneksi.

4. Penggunaan Izin Perangkat Android

  • Akses Jaringan (`INTERNET`, `ACCESS_NETWORK_STATE`): Digunakan untuk membuka soket TCP/UDP RDP, deteksi profil jaringan lokal, dan Wake-on-LAN. Penghitung sesi anonim aktif secara default; selama sesi RDP tersambung aplikasi mengirim heartbeat HTTPS dengan ID acak sementara. Fitur ini dapat dimatikan di Pengaturan > Keamanan.
  • Layanan Latar Depan (`FOREGROUND_SERVICE`): Digunakan untuk mempertahankan sesi RDP ketika aplikasi berpindah ke latar belakang, sesuai batasan Android.
  • Mikrofon (`RECORD_AUDIO` — Opsional): Hanya diakses apabila pengguna mengaktifkan pengalihan mikrofon pada profil koneksi terkait.
  • Penyimpanan Lokal (Opsional): Digunakan untuk pengalihan folder Drive 'XyDesk', berkas yang dibagikan lewat Android, dan rekaman MP4 desktop PC remote yang dimulai pengguna. Rekaman hanya berisi frame PC remote (bukan layar HP atau audio), disimpan di `Movies/XyDesk` atau folder aplikasi pada Android versi lama, dan tidak diunggah ke server XyDesk.

5. Perlindungan Privasi Sesi Lokal

Pengguna dapat mengaktifkan fitur perlindungan tambahan di menu Keamanan aplikasi, meliputi blokir tangkapan layar (`FLAG_SECURE`), autentikasi kunci layar/biometrik perangkat sebelum membuka sesi, penguncian sesi Windows otomatis (`Win+L`) saat terputus, serta pembersihan clipboard HP otomatis setelah sesi berakhir.

6. Statistik unduhan situs dan sesi aktif

Penghitung unduhan membaca agregat jumlah unduhan aset APK dari GitHub Releases yang masih tersedia. Angka tersebut menghitung unduhan berkas, bukan orang unik. Secara terpisah, penghitung sesi RDP anonim aktif secara default dan dapat dimatikan kapan saja melalui sakelar di Pengaturan > Keamanan. Saat sesi tersambung, aplikasi mengirim ID UUID acak baru untuk sesi tersebut dan heartbeat setiap 30 detik. Server menyimpan hash ID serta waktu heartbeat saja, menghapus lease saat sesi berakhir, dan menandai lease kedaluwarsa setelah 90 detik tanpa heartbeat (pembersihan berjalan berkala). Alamat PC, nama profil, username, password, clipboard, dan isi layar tidak dikirim. Cloudflare tetap memproses metadata jaringan seperti alamat IP untuk melayani permintaan; alamat tersebut tidak disimpan oleh penghitung sesi. Angka publik adalah perkiraan sesi klien yang mengirim heartbeat, bukan pengguna unik atau seluruh koneksi RDP, dan tidak menyimpan riwayat sesi.
