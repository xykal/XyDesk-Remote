# Audit: controls, FreeRDP, certificates, ports — 2026-09-29

**Product attribution:** XyVerse Technology Global

**Scope:** Reported failure of added HUD controls/mapping and layout reset; poor-network behavior; connection-time certificate decisions; port entry; remote drive label (`XyDesk`); and native queue hardening. Source audit started against `main` at `558d4ae` plus uncommitted draft diff `034b7f4`.

## Prioritized findings and fixes

1. **[CRIT] Added HUD keyboard and combo buttons sent raw Android `KeyEvent.KEYCODE_*` integers as Windows `VK_*` codes.** `SessionSurfaceController.kt:269` called `inputManager?.processVirtualKey(keyCode, down)`, which forwards directly to `LibFreeRDP.sendKeyEvent` (`android_freerdp.c:1068: GetVirtualScanCodeFromVirtualKeyCode(keycode, 4)`). Because `HudKeyCatalog` (`HudKey.kt:188-291`) stores Android `KEYCODE_*` constants, every added key/combo either sent the wrong key (`Enter`=66 -> `VK_KEY_B`, `Backspace`=67 -> `VK_KEY_C`, `Esc`=111 -> `VK_DIVIDE`, `Ctrl`=113 -> `VK_F2`, `Alt`=57 -> `VK_KEY_9`, `Win`=117 -> `VK_F6`) or produced scancode `0` (`Tab`, `Space`, `Shift`, `A-Z`, `Ctrl+C`, `Ctrl+V`). `KeyboardMapper.keymapAndroid` also lacked `CTRL_LEFT/RIGHT`, `SHIFT_LEFT/RIGHT`, `ALT_LEFT/RIGHT`, `META_LEFT/RIGHT`, and `MENU`. **Fix applied:** added `KeyboardMapper.translateAndroidKeyCode` and `SessionInputManager.sendAndroidKeyCode`, routed `SessionSurfaceController.sendVirtualKey` through it, rejected `scancode == 0` in `android_freerdp.c`, and added JVM unit tests covering 100% of `HudKeyCatalog` keys and combos.
2. **[HIGH] HUD layout reset when dragging multiple buttons, and 8 px (~2 dp) movement threshold dropped taps.** `SessionKeyLayer.kt:101-237` captured `onDrag`, `onPhase`, and `onEdit` inside a non-restarting `pointerInput` block without `rememberUpdatedState`; dragging a second button invoked a stale `onMove` closure that overwrote previously moved buttons back to their old positions. In addition, `travelled > 8f` raw pixels (~2 dp) set `dragged = true` even in normal use mode (`mappingMode == false`), cancelling taps on `COMBO`, `TOGGLE`, `SCROLL_UP/DOWN`, and `INPUT_SWITCH` controls whenever a thumb wobbled, and preventing taps from opening `HudKeyEditor` in layout mode. **Fix applied:** wrapped callbacks/bounds in `rememberUpdatedState`, keyed each button by `key.id`, gated drag/scroll gesture start via `shouldStartHudButtonGesture` using `viewConfiguration.touchSlop` only for `mappingMode` or `SCROLL_SLIDER`, and set `defaultAction` (`TOGGLE` for standalone modifiers, `HOLD` for hold-drag click).
3. **[HIGH] Native input dequeue was O(n) per event and HUD cursor state desynced in direct-touch mode.** `android_event.c:28-90` shifted the entire array via `memmove` on every pop and lacked teardown guards inside the lock; in `XyDeskSession.kt:570-605`, direct touch (`SessionView`) did not update `cursorX`/`cursorY`, so HUD clicks/scrolls acted at the screen center, and `boundInstance != 0L` could block cursor dispatch before `LaunchedEffect` bound the instance. **Fix applied:** O(1) circular queue with adjacent pure `PTR_FLAGS_MOVE` coalescing and teardown guards, immediate `inputManager.attachSession` on `bind`, cursor-position sync from `SessionInputManager` to `XyDeskSession`, and throttled content-free failure notices.
4. **[MED] Poor-network tuning and certificate UI.** `RdpOptions.kt:47-55` and `RdpUri.kt:57-72` lacked an opt-in low-bandwidth profile; `XyDeskSession.kt:1542-1620` and `Screens.kt:666-710` expanded certificate details and saved fingerprints by default. **Fix applied:** opt-in `lowBandwidth` (`broadband-low` + `AVC420` when H.264 is enabled), collapsible certificate details and trusted list, and "Tolak kali ini" / "Deny this time".
5. **[LOW] Single-field `host[:port]` address input and `XyDesk` remote drive label.** `AddDeviceScreen.kt:75-220` and `RdpUri.kt:21-65` split host and port and labeled the redirected folder `sdcard`. **Fix applied:** `RdpEndpoint.kt` parses/formats `host[:port]` (default 3389 omitted in UI, bracketed IPv6 with custom port) and sets the drive label to `XyDesk` while keeping `sdcard` URI compatibility in `LibFreeRDP.java`.
