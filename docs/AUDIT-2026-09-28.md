# Audit XyDesk Remote — 2026-09-28

Scope: Android session controller, HUD button editor/slider, session palette, app theme, settings flow, and release/test wiring. Source compared with `main` at `dea7dd3c9c8ff547f55dab2b7de3501ce491923`; workspace snapshot differs only in `release.properties` (stale `0.5.8/25` vs main `0.5.9/26`). Current successful release baseline: [Actions run 36489358236](https://github.com/xykal/XyDesk-Remote/actions/runs/36489358236). No local build or device session was run; this is a scoped source audit, not a full security review.

## Findings

1. **[HIGH] HUD size editor keeps a stale draft.** `SessionControls.kt` `replace()` forwards edits but never updates `editing`; `HudKeyEditor` continues receiving the original `HudKey`. The persisted HUD model may change while the slider thumb and preview stay stale, making the in-session size control appear stuck. Fix: update the editor draft and persistence state together; add a regression test for live value mapping.
2. **[HIGH] A selectable HUD palette paints an almost opaque white plate.** `SessionPrefs.kt` `HudPlate.LIGHT` maps to `Color(0xE6FFFFFF)` in `SessionKeyLayer.kt`. This palette is independent of app theme, so it can put a white disc behind icons in dark mode. Fix: keep persisted enum ordinals but replace this style with a dark translucent variant; keep remote-canvas controls contrast-safe.
3. **[MED] The custom slider lacks accessibility semantics and automated UI coverage.** `XyControls.kt` implements drag with raw `pointerInput`; it exposes no slider role/progress action. `app/build.gradle` has no app test dependency and CI only runs `core-rdp` JVM tests plus Kotlin compilation. Fix: add progress semantics and pure value-mapping tests to the existing CI gate; physical touch still needs device validation.
4. **[MED] Session overlays mix theme-aware and hard-coded colors.** Editor/panel surfaces use `MaterialTheme`, while `HudMappingBanner` and control plates hard-code white/dark colors. A dark app therefore has a few visibly bright surfaces. Fix: use semantic theme colors for editor chrome and a documented dark, translucent palette over the remote framebuffer.
5. **[MED] Product policy files are incomplete or ambiguous.** Root `SECURITY.md` is FreeRDP's upstream policy, not a XyDesk reporting policy; there is no root `THIRD_PARTY_NOTICES.md`, `PROGRESS.md`, or `IDEAS.md`. `AboutSection` says `XyVerse / xykal`, not the exact `Powered by XyVerse Technology Global` attribution. Fix: add the task progress/ideas/design records and a single app brand constant; retain upstream FreeRDP policy unchanged.

## Cross-cut notes

- Existing settings already include app theme (system/dark/light), input mode, pointer size, scroll speed, haptics, and HUD default size. Do not duplicate them; improve discoverability and live behavior first.
- `HudPlate.DARK` is currently the default for fresh preferences; existing users can retain `LIGHT`, which explains why the white plate can persist.
- `docs/XYDESK-REMOTE-NOTICE.md` records FreeRDP modifications, but does not replace a complete third-party notice inventory.
- App purpose: Android RDP client, direct connection to user-selected Windows hosts. The About screen offers voluntary support links; a documented revenue/maintenance plan is absent. This is a documentation gap, not a blocker for the requested controller work.
- Security review was limited to the touched UI/settings paths; no claim of a comprehensive dependency, protocol, or credential audit is made.
